# 讓大家都能一鍵登入 —— 設定一次就好

這份只需要做**一次**。做完之後，任何人打開這個 App，都只要按一下
「用 Google 帳號登入」，就能看到自己的行事曆。

總共兩件事：**開網站**（3 分鐘）、**拿一串登入代碼**（5 分鐘）。

---

## 第一件事：把網站打開（不用動手）

把這個分支合併到 `main` 之後，部署會自動跑，也會自動把 GitHub Pages 打開。
等一兩分鐘，你的網站就會出現在：

```
https://evischu.github.io/pig-daily/
```

進度可以在 repo 的 **Actions** 分頁看，綠色勾勾＝上線了。

> 這時候打開已經可以用了，只是還沒有登入按鈕——第二件事做完就會有。
>
> 萬一部署失敗、訊息提到 Pages 沒有啟用，再手動開一次：
> **Settings → Pages → Source 選 GitHub Actions**，然後到 Actions 分頁
> 按 **Re-run jobs**。

---

## 第二件事：拿一串登入代碼（5 分鐘）

Google 規定：任何想讀你行事曆的 App，都要先跟 Google 報到、拿一串代碼。
這串代碼叫「用戶端 ID」，長得像 `1234567890-abcdefg.apps.googleusercontent.com`。

**全程在電腦上操作，照著按就好。**

### 1. 建一個專案

1. 打開 <https://console.cloud.google.com/>
2. 用你的 Google 帳號登入
3. 左上角有個專案選單，點它 → **新增專案**
4. 名稱打 `Dayline`，按**建立**，等它跑完

### 2. 打開行事曆功能

1. 左上角選單（三條線）→ **API 和服務** → **程式庫**
2. 搜尋 `Google Calendar API` → 點進去 → 按**啟用**
3. 再搜尋一次 `Google Tasks API` → 點進去 → 按**啟用**

### 3. 填同意畫面

這是使用者按下登入時會看到的那一頁。

1. 左邊選 **API 和服務** → **OAuth 同意畫面**
2. 使用者類型選 **外部**，按**建立**
3. 填三個必填欄位：
   - 應用程式名稱：`Dayline`
   - 使用者支援電子郵件：你的信箱
   - 開發人員聯絡資訊：你的信箱
4. 一路按**儲存並繼續**，到最後按**返回資訊主頁**
5. 在 **測試使用者** 區塊，按**新增使用者**，把要用這個 App 的人的
   Gmail 一個個加進去（**包含你自己**）

> ⚠️ 這一步很重要：**沒有被加進測試使用者的人，會登入失敗**。
> 上限 100 人。要開放給更多人，看最下面的「想給更多人用」。

### 4. 拿到代碼

1. 左邊選 **API 和服務** → **憑證**
2. 上方按 **建立憑證** → **OAuth 用戶端 ID**
3. 應用程式類型選 **網頁應用程式**
4. 名稱打 `Dayline Web`
5. 在 **已授權的 JavaScript 來源**，按**新增 URI**，貼上：

   ```
   https://evischu.github.io
   ```

   > 只貼到網域為止，**後面不要加 `/pig-daily`**，也不要有結尾斜線。

6. **已授權的重新導向 URI** 留空不用填
7. 按**建立**
8. 畫面會跳出一串 **用戶端 ID**，按旁邊的圖示複製

### 5. 把代碼貼進去

1. 回到 <https://github.com/evischu/pig-daily>
2. 進 `calendar-app` 資料夾 → 點 `config.js`
3. 按右上角的**鉛筆圖示**（編輯）
4. 找到這一行：

   ```js
   googleClientId: "",
   ```

   把剛剛複製的代碼貼進兩個引號中間，變成：

   ```js
   googleClientId: "1234567890-abcdefg.apps.googleusercontent.com",
   ```

5. 右上角按 **Commit changes** → 再按一次 **Commit changes**

等一兩分鐘，重新整理網站——**登入按鈕就出現了**。

## 使用者要做什麼

只有三步，沒有任何設定：

1. 用手機打開 `https://evischu.github.io/pig-daily/`
2. 按 **用 Google 帳號登入** → 選帳號 → 允許
3. 按手機的**分享**按鈕 → **加入主畫面**

從此桌面上就有一個 Dayline 圖示，點開就是 App，沒有網址列。

---

## 想給更多人用

測試模式上限 **100 人**。要開放給所有人，需要送 Google 審核：

- 在 **OAuth 同意畫面** 按「發布應用程式」，然後送出驗證
- 要準備：隱私權政策網址、網域所有權驗證、用途說明、一段示範影片
- 審核大約 **2 到 6 週**，**免費**

這個 App 刻意設計成**不把任何行程存到伺服器**（資料只在手機和 Google
之間往返），所以只需要一般的 OAuth 驗證，不需要每年花錢做第三方安全稽核
（CASA，約 US$500–4,500／年）。

---

## 出問題時

| 畫面上寫什麼 | 怎麼修 |
|---|---|
| `redirect_uri_mismatch` 或 `origin mismatch` | 第 4 步的「已授權的 JavaScript 來源」填錯。要剛好是 `https://evischu.github.io`，不能有路徑或結尾斜線 |
| `access_blocked` / 這個應用程式未經驗證 | 那個 Gmail 還沒被加進**測試使用者** |
| 沒有出現登入按鈕 | `config.js` 沒存到，或網站還在部署。等兩分鐘重新整理 |
| 登入成功但沒有行程 | 第 2 步的 Google Calendar API 沒有啟用 |

改完 `config.js` 後，到 repo 的 **Actions** 分頁可以看到部署進度；
綠色勾勾出現就代表新版上線了。
